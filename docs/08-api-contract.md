# 08 — API contract

Base: `https://api.balise.fr/v1`. JSON everywhere, `application/json`, UTF-8, RFC 3339 timestamps in
UTC. Errors follow RFC 9457 (`application/problem+json`). OpenAPI generated by FastAPI at
`/v1/openapi.json`.

> **v1 vs v2.** Endpoints and fields marked 🔌 are **specified now, implemented in v2**
> ([06](06-availability-strategy.md)). In v1 they exist in the OpenAPI schema and return
> `501 availability_not_enabled`:
>
> ```json
> {"type":"https://balise.fr/problems/availability-not-enabled","title":"Availability is not enabled",
>  "status":501,"detail":"Live availability is not part of this release. See /a-propos/donnees."}
> ```
>
> The `status` field is **present and `null`** on every spot payload in v1, so a client written
> against v1 keeps working unchanged when v2 populates it. Specified-and-refusing beats undefined —
> it also means the frontend, the generated TS types and the docs never need a breaking change.

## Conventions

- IDs are opaque strings (`"spot_18421"`, `"harbour_312"`).
- Pagination: `?limit=` (default 50, max 500) + `?cursor=` opaque.
- Every response carrying data derived from a licensed source includes an `attribution` array.
- `ETag` + `If-None-Match` on all GETs. `Cache-Control` per [07](07-architecture.md).
- Rate limits: 60 req/min anonymous per IP, 600/min for a feed token. `429` + `Retry-After`.
  `/v1/tiles/*` is counted in a **separate 1 200/min bucket**: one "télécharger cette zone" is
  hundreds of legitimate tile requests, and it must never spend the sailor's read budget.

## Public read

### `GET /spots`
Query spots in a bounding box.

| Param | Type | Notes |
|---|---|---|
| `bbox` | `minlon,minlat,maxlon,maxlat` | required, max 2° span |
| `kind` | csv of `mooring_buoy,berth,anchorage,pile,quay` | |
| `max_draft_m`, `max_loa_m` | number | boat filter: returns spots that *fit* the boat |
| `visitor` | bool | |
| `sort` | `distance` (default), `price` | v2 adds `confidence` |
| `format` | `geojson` (default) | |
| 🔌 `state` | csv of `free,occupied,unknown` | v1: `501` if supplied |
| 🔌 `min_confidence` | 0..1, default 0.3 | v1: `501` if supplied |

```json
{
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "id": "spot_18421",
    "geometry": {"type": "Point", "coordinates": [-2.9021, 47.5412]},
    "properties": {
      "kind": "mooring_buoy", "code": "B14", "harbour_id": "harbour_312",
      "field_id": "field_88", "visitor": true,
      "depth_m": 2.4, "max_loa_m": 12.0, "max_draft_m": 2.0,
      "status": null,
      "price_per_night_cents": 2800
    }
  }],
  "attribution": ["Shom, 2026 (Licence Ouverte 2.0)", "© OpenStreetMap contributors (ODbL)"]
}
```

`status` is `null` in v1. In v2 the same key carries:

```json
"status": {"state": "free", "confidence": 0.86, "as_of": "2026-08-06T13:41:30Z",
           "source_kind": "port_feed", "age_seconds": 154}
```

**Clients must treat `status: null` as "unknown", not as an error** — that is the whole contract.
It is also the correct v2 behaviour for any spot nobody has reported, so the null case never goes
away and clients never get to skip handling it.

### `GET /spots/{id}`
Full sheet: spot + field + harbour summary + `tide` (next HW/LW and depth at next LW) + `weather`
(next 48 h summary). 🔌 v2 adds the last 5 observations (source kind and age only, never contributor
identity).

### 🔌 `GET /status?bbox=…&since=…` *(v2)*
The volatile companion to cached tiles. Compact, no geometry:

```json
{"as_of":"2026-08-06T13:45:00Z",
 "spots":{"18421":["free",0.86,"2026-08-06T13:41:30Z","port_feed"],
          "18422":["occupied",0.7,"2026-08-06T12:02:00Z","community"]},
 "fields":{"88":{"free":5,"capacity":48,"confidence":0.9}}}
```

### `GET /harbours/{slug}`
Harbour sheet: contacts, VHF, services, prices, opening hours, links to the official site, and
fields with `capacity` / `visitor_capacity`. 🔌 v2 adds `free_count` per field. In v1 the sheet's
call-to-action is the **capitainerie phone/VHF** — the honest substitute for availability.

### `GET /harbours?q=&near=lon,lat&limit=`
Search by name (trigram) or proximity.

### `GET /navaids/{id}`
One navigation mark, **with the S-57 codes translated into French plain language**:

```json
{"id":"navaid_9931","s57_class":"boylat","label":"Bouée latérale bâbord",
 "colour":"rouge","shape":"cylindrique","topmark":"cylindre rouge",
 "light":{"text":"Fl R 4s","character":"À éclats","period_s":4,"colour":"rouge","range_nm":7},
 "name":"Le Grand Mouton", "position":[-2.87,47.53],
 "source":"Shom, 2026"}
```

### Tiles

```
GET /tiles/navaids/{z}/{x}/{y}.mvt      z 8–16, layer "navaids"
GET /tiles/spots/{z}/{x}/{y}.mvt        z 10–18, layer "spots" (geometry + static attrs only)
```

Generated with `ST_AsMVT` ([07](07-architecture.md)). **No status in tiles.** `ETag` includes the
referential version; a re-ingest bumps it and invalidates cleanly.

### `GET /tides?harbour=…&from=&to=` · `GET /weather?harbour=…`
Cached predictions. Both return the source attribution and a `is_estimate: true` flag.

## Contribution

### `POST /issues` *(v1)*
Report bad **referential** data — wrong position, buoy removed, wrong price, wrong contact.

```json
{"target":{"type":"spot","id":"spot_18421"},"kind":"wrong_position",
 "note":"la bouée est ~40 m plus au sud","position":[-2.9024,47.5407],
 "client_id":"<opaque device token>"}
```

`202` into a moderation queue → reviewed → lands as a PR on `overrides.yml`
([10](10-ingestion-pipelines.md)). This is v1's contribution loop: it improves *what the object is*,
never *what state it is in*.

### 🔌 `POST /reports` *(v2)*
```json
{"spot_id":"spot_18421","state":"occupied","observed_at":"2026-08-06T13:40:00Z",
 "position":[-2.9020,47.5411],"client_id":"<opaque device token>","note":"3 bateaux sur coffre"}
```
- `201` with the resulting `status` object so the client can update optimistically.
- Server clamps `observed_at` to `[now-6h, now+5min]`.
- Plausibility: `position` must be within 500 m of the spot, else `confidence` is halved and
  `payload.remote=true` is recorded.
- Idempotency via `Idempotency-Key` header (offline queue may retry).

### 🔌 `POST /reports/batch` *(v2)*
Offline flush, max 100 reports, same semantics, partial success reported per item.

## 🔌 Partner feeds — MBFS *(v2)*

### `POST /feeds/{feed_id}/observations`
`Authorization: Bearer <token>`. Body per [06](06-availability-strategy.md). Returns
`{"accepted": 42, "rejected": [{"index": 7, "reason": "unknown spot_id"}]}`.
Rejections never fail the whole batch.

### `PUT /feeds/{feed_id}/snapshot`
Full state replacement for a harbour — simpler for vendors than computing deltas. Any spot absent
from the snapshot becomes `unknown` after `ttl`.

### `GET /feeds/{feed_id}/health`
Last received, expected `ttl`, current staleness, rejection rate over 24 h. Given to the partner so
they can monitor themselves.

## 🔌 Realtime *(v2)*

v1 has no websocket. The client's data layer is written against a `subscribe(bbox, onUpdate)`
interface whose v1 implementation is a no-op — same seam as the backend provider
([06 §A/S2](06-availability-strategy.md)).

```
WS /v1/stream
→ {"subscribe": {"bbox": [-3.1,47.4,-2.7,47.7]}}
← {"type":"status","spot_id":"spot_18421","state":"free","confidence":0.86,
   "as_of":"2026-08-06T13:41:30Z","source_kind":"port_feed"}
← {"type":"heartbeat","at":"…"}
```
One subscription per connection, bbox max 1°. Server drops connections idle > 120 s without a pong.
Client falls back to `GET /status?since=` polling every 20 s when the socket is unavailable.

## Auth

| Actor | Mechanism | v1 |
|---|---|---|
| Anonymous sailor | Opaque device token issued by `POST /devices`, stored in localStorage; carries no PII | ✅ (for `/issues`) |
| Harbour operator | Email magic link → JWT, scoped to claimed harbours | ✅ (claim flow) |
| Account | Email magic link → JWT (15 min) + refresh cookie (30 d, `HttpOnly`, `SameSite=Lax`) | ✅ |
| 🔌 Partner feed | Long-lived bearer token, hashed at rest, rotatable, scoped to one `feed_id` | v2 |
| Admin/moderation | Separate app, SSO, not exposed on the public API surface | ✅ |

## Open data endpoints

- `GET /opendata/referential-osm.geojson` — ODbL share-alike discharge ([04 §2](04-licensing-and-legal.md)) *(v1)*
- 🔌 `GET /opendata/mbfs` — the feed spec + JSON Schema *(published in v2; drafted in `docs/mbfs/` in v1)*
- 🔌 `GET /opendata/stats.json` — aggregate occupancy by harbour/month, no vessel identity *(v2)*

## Versioning

URL-versioned (`/v1`). Additive changes only within a version. Deprecations announced 6 months ahead
via `Sunset` header and the changelog.
